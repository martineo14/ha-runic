What the Runic.io integration does

It connects your Runic GPS trackers to Home Assistant in two ways: it reads where each vehicle is, and it passes Runic alerts (started moving, entered a zone, theft…) to your automations within seconds. Alerts arrive over a connection Home Assistant opens itself, so nothing on the internet needs to reach your Home Assistant.

From the tracker to your automation

Runic cloud

Your tracker reports in

  • The vehicle's position and moving / stopped state are kept by Runic.
  • An alert rule you created in the Runic app fires, for example “vehicle started moving”.
  • Runic sends that alert over the real-time stream your Home Assistant opened. No URL or signing secret is involved.
The integration

Checks it, then announces it

  • Drops repeats of an alert it already handled.
  • Saves the alert's sequence number (seq), so after a restart it carries on where it stopped.
  • Fires the vehicle's trigger for that alert type, for example “Theft alarm”.
  • Moves the vehicle on the map and records the alert on its “Last alert” entity.
  • If the connection drops, it reconnects and resumes on its own.
Your Home Assistant

You decide what happens

  • An automation using that trigger runs: notify your phone, turn on lights, open the garage.
  • The vehicle shows on the map and in zones like Home.
  • The location, speed and “moving” entities can trigger automations too.

Two ways data comes in

Every 5 minutes, and after each alert

Home Assistant asks Runic

It calls GET /vehicles and GET /vehicles/{id} with your API token. For each vehicle it keeps three entities up to date:

device_tracker.<vehicle>: latitude and longitude, so it appears on the map.
sensor.<vehicle>_speed: GPS speed of the last fix, in km/h.
binary_sensor.<vehicle>_moving: on when the last fix is under 15 minutes old and at 5 km/h or more.

Runic's own RUN status only means the tracker is active (heartbeats, ignition), so it isn't used for “moving”.

Home Assistant only makes outgoing requests, so nothing on the internet needs to reach it.

Seconds after an alert

Runic streams alerts to Home Assistant

Home Assistant opens an outgoing connection to wss://api.runic.io/v1/alerts/stream with your API token, and Runic sends each alert down it. This is what triggers automations. It covers 20 alert types, including alert.movement, alert.poi_area (entered or left a zone), alert.theft, alert.tow, alert.speed_limit and alert.low_battery.

Needs only your API token, a “Real-time stream” endpoint in the Runic developer portal with the alert types ticked, and an alert rule in the Runic app for each type. No public URL, port forwarding, Nabu Casa or tunnel: it works behind any router, even on 4G. A diagnostic “Alert stream” sensor on the Runic.io device is on while the stream is connected.

Set up: in the developer portal, Add endpoint → Real-time stream (one per company, no URL, no secret). In Home Assistant, add Runic.io, paste the API token and choose Real-time stream (recommended). Send test event on the endpoint sends alert.test to every connected client.

Webhooks still work as an alternative. They are signed, and need Home Assistant reachable over public HTTPS with no redirects. Setups that already use a webhook keep it, and can turn the stream on under Runic.io → Configure. Both can run together: alerts are deduplicated on their id.

Set up triggers

Each Runic vehicle is a device in Home Assistant. You can trigger on a Runic alert, or on a change to the vehicle's location, speed or moving entities. Pick the one that matches what you want to react to.

Runic alert triggers need a stream (or webhook) endpoint in the Runic developer portal with that alert type ticked, plus an alert rule in the Runic app. Polling only triggers work with nothing else to set up.

Add a Runic alert trigger in the editor

  1. Go to Settings → Automations & scenes → Create automation → Create new automation.
  2. Click Add trigger, then the By target tab.
  3. Under Devices, click your vehicle, for example Truck 3. Don't open its child entities.
  4. On the right, pick the alert: Theft alarm, Entered a point of interest, Speed limit exceeded…
  5. Add your actions under Then do, then Save.

Alternative: By type → Device → choose the vehicle → choose the alert. To use the same trigger for several vehicles, add one trigger per vehicle in the same automation. The examples below are YAML. To use one, open ⋮ → Edit in YAML in a new automation, paste it, then switch back to the visual editor and pick your own vehicle and phone.

    Information you can use in messages

    Inside an automation started by a Runic alert, these templates hold the alert's details:

    • {{ trigger.event.data.vehicle_name }}, {{ trigger.event.data.plate }}
    • {{ trigger.event.data.alert }}: the alert type, e.g. theft
    • {{ trigger.event.data.level }}: info, warning or critical, as set on the Runic rule
    • {{ trigger.event.data.message }}: Runic's text, in your account's language
    • {{ trigger.event.data.position.lat }}, {{ trigger.event.data.position.lon }}
    • {{ trigger.event.data.poi_name }}, {{ trigger.event.data.direction }}: for geofences
    • {{ trigger.event.data.source }}: stream or webhook, how the alert arrived

      What version 0.5.0 doesn't do yet
      
    
        
      
      • The “moving” sensor only switches off at the next 5-minute poll. Runic has no “stopped” alert.
        • 
      
      • No sensors yet for battery voltage, fuel or odometer, though Runic's API has them.
        • 
      
      • Vehicles added to your Runic account later only appear after you reload the integration.
        • 
      
      • If Home Assistant is disconnected from the stream for more than 72 hours, the alerts from that gap are lost: Runic keeps only 72 hours. The integration refreshes the vehicles over REST instead.
